# Cursor への頼み（11/18）: 拡張の「人の動き」の送り方を、少しずつ・間を空けて送る形に

> 竹内さんへ: 下の「ここから」〜「ここまで」をそのまま Cursor に貼ってください。

---ここから---

Chrome 拡張（chrome-extension/）の「人の動き」の送り方を直してください。サーバー（/api/human-motion）は触らなくて大丈夫です（サーバー側の守りはもう入れてあります）。

## 何が起きたか
- 11/18 12:16〜12:22（日本時間）に、DB の時間切れが約20秒まとまって出ました。
- 同じ時間に、拡張から `/api/human-motion` への POST が5分で241件（12:00 台は390件）一度に来ていました。普段は0件です。
- 拡張を開いているタブや PC が多いと、同じ時刻（1分ごと・タブを離れる時）に一斉に送るため、DB の書き込みが重なります。

## 直してほしい事
1. **送る前に貯めて、まとめて送る**
   - `axlx-human-motion`（background.js 1831行付近）の1回分を、すぐ送らずに `chrome.storage.local` の送り待ちに貯める。
   - 貯まった分を、最大50件ずつ1回の POST にまとめて送る（body は `{ "items": [ … ] }` の形）。
   - サーバーが1回で受け取れる形はこちらで用意します。それまでは今の1件ずつの形で、下の 2・3 だけ先に入れてください。
2. **送る時刻をずらす**
   - 送る間隔に、PC ごとにばらつき（例: 60秒 ± 0〜30秒のランダム）を入れる。全員が同じ秒に送らないようにします。
   - 続けて送る時は、1回ごとに 2秒以上空ける。
3. **失敗した時は捨てずに後で送り直す**
   - 応答が 429・5xx・時間切れの時は、送り待ちに戻す。
   - 次は 30秒 → 60秒 → 120秒 と間を広げて送り直す（最大5回）。
   - 送り待ちは最大500件まで。超えたら古い物から捨てて、console に件数を出す。
   - 今は `!res.ok` の時に console に出すだけで、データが落ちています。
4. **写真付き（human-shot・3069行付近）は今まで通り1件ずつ**
   - 大きいので、まとめません。ただし 2 の「時刻をずらす」と 3 の「送り直し」は同じように入れてください。

## 守ってほしい事
- 送る中身は今まで通り「数と傾向だけ」。入力した文字・お客様の名前・電話は送らない。
- 鍵（x-automation-key）は今まで通り background.js で付ける（ページに出さない）。
- 学習そのもの（何を記録するか）は変えない。送り方だけ変える。

## 確かめ方
- タブを3つ開いて通常モードで数分動かし、Network で `/api/human-motion` の POST が、ばらけた時刻・50件以下のまとまりで出ているかを見る。
- サーバーを止めた（オフライン）状態で動かし、戻した後に送り待ちの分が間を空けて送られるかを見る。

## メモ（作業員H・統括役向け）
- サーバー側の守り: `app/lib/human-motion-pacer.ts`（HUMAN_MOTION_PACE・既定 on）。10秒に8回を越えて重なった時は受け取りだけ返して、1.5秒ごとに25行ずつまとめて書く。拡張は 429 を送り直さないので、429 は返さない。
- `{ items: [...] }` の一括の受け口は、拡張の直しが入る時にこちらで足す（今は1件の形だけ）。
