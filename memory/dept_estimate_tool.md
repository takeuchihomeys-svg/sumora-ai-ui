## 🔴 最初に読む: 見積書の金額文は `app/lib/estimate-body.ts` 1本（竹内・2026-09-20・H さん事例）— 黄金ルール

**金額文をどこかに書き足す前に必ずここを読む。同じ物を5か所目に書かない。**

| 使う場所 | 関数 |
|---|---|
| 見積書作成画面の LINE テキスト | `buildEstimateMessage([...], { dayRentNote: !moveInDate })` |
| 画面の節約額バッジ | `buildSavingsLine(アカウント名, calcSavings(...))` |
| AIX【見積書送る】1枚 | `buildEstimateMessage([...])` |
| AIX【見積書送る】複数枚 | `buildEstimateItem(...)` を連結＋`DAY_RENT_NOTE` |
| AIX【物件確認した】の見積 | 同上 |

**決まった構成**（実送信365日 319通: 割引 97%・節約 92%・日割注記 99%・🌟 97%）
```
【物件名 号室】

初期費用さらに          ← 割引額がある時だけ
🌟NN,NNN円割引させて頂き   ← 同上
初期費用：NNN,NNN円

〇〇なら一般的な不動産業者よりNNN,NNN円節約出来ます！！   ← ★割引と独立

※ご入居日によって日割家賃が発生致します。
```

**⚠ 何が壊れていたか**: AIX 1枚の経路だけ `if (discount > 0 && total > 0)` と**割引と節約を抱き合わせ**にしていた。
H さんの見積書は**スモ割 0円**だったので「初期費用：178,090円」だけになり、見積書の画像に印字されている
**節約 61,920円が本文から消えた**。他の3経路は元から独立していた（＝正しい3か所が仕様書だった）。
実送信で割引なし＋節約ありは3通あり（ROCCO・グレイス ガーデン・マンションサンパール）、どれも節約行を書いている。

**節約額の式**（`calcSavings`・画面のバッジと本文で同じ数字にする）
`max(0, round(家賃 × 1.1) − (仲介手数料 + 消費税) + 割引額)`　家賃が読めない時は 0＝節約行を出さない。

**⚠ 2通目（カバーレター）に金額を書かない**（`app/lib/estimate-cover.ts`）
実送信のカバーレター835通で金額を含むのは**5通（1%）**・【物件名】を含むのは**6通（1%）**。
本番で**別の物件の金額文（【プレサンス阿倍野松崎805号室】…152,000円）が丸ごと写る**事故が出た。
出口だけ広げても AI は形を変えて写す（箇条書きに合体・〇でマスクされたまま）ので、
**入口（☆成功実例）にも同じ関数を通して写す元を無くした**。
誤削除0の線: 【物件名】の行は**直後が金額行の時だけ**／日割注記は**同じ文に金額行がある時だけ**落とす。
（この線を外すと「④【希望築年数】」＝条件ヒアリングフォームの項目まで消える）

**⚠ 2通目は「通す条件」で決める — 落とす物を並べない**（竹内・2026-09-20・3回目の検証）
出口に落とす形を足しても AI は形を変えて出し続けた（**5回変わった**）。
カバーレターは**無くても困らない**（1通目の見積書が本体）ので、
「落とす物を並べる」のをやめて「**通す物を決める**」形にした。
→ **本文に「見積」が1度も出てこない2通目は送らない**。
実送信365日のカバーレター相当 859通は**全部「見積」を含む**（落ちるのは0通）。
一方、本番で出た「お申込み情報を確かに受け取りました」「出力は行いません」
「内容をこちらで確認することができない状態でございます」はどれも落ちる。

**⚠ 2通目のプロンプトには「今回の物件名」を渡す**（竹内・2026-09-20・2回目の検証で発見）
カバーレターのプロンプトに**物件が1つも渡っていなかった**。そのため AI は会話履歴だけを見て、
「物件も特定できていないため送付内容の言及も不可能です」と作業メモを返したり、
直近の話題（申込書類）に引っ張られて「お申込み情報を確かに受け取りました」と**見積書と無関係な文**を書いていた。
→ 1通目（`message_text`）の `【…】` から物件名を取って渡す（1枚でも複数枚でも同じ材料になる）。
**金額は渡さない**（1通目にあるので重複禁止）。
※ 出口を足すだけでは形を変えて出続ける（金額の混入→箇条書き→〇でマスク→見出しごと写す→作業メモ、と5回変わった）。
  材料が足りないのが原因なら**入口に材料を渡す**のが根本の直し。

**⚠ 2通目の出口は `sanitizeCoverLetter` 1本**（竹内・2026-09-20「色んなパターンで確認」）
本番14パターンで回したら、**1通目は14/14 正しい**のに2通目に**7種類の欠陥**が出た。
どれも実送信365日 11,998通で0通なので落として安全（836通に当てて誤削除0）。

| 本番で出た2通目 | 直し方 |
|---|---|
| **【お客様に送る文】** / **【お客様の現在の状況（状態）】**お申込み情報を… | 見出しだけ外して本文は残す |
| **【お客様名】さん**お世話になっております | 名前に**置き換える**（外すと「さんお世話に…」と壊れる） |
| ○○さんお気に召されましたら | 同上（ナレッジの principle 由来） |
| お世話になっております。**ギガ賃貸です。** | その文だけ落とす（挨拶は残す） |
| **鈴木さん**お世話になっております（スタッフ名） | 顧客名に直す。**呼び名が「お客様」の時はやらない**（「お客さん」になる） |
| **〈**（1文字） | 2通目を送らない（1通目は正常に送れる） |
| こちらのメッセージには**返信できません** | `isNotACustomerReply` で落とす |
| 他の物件の金額ブロック | `stripEstimateAmountBlock`（下記） |

⚠ **順番に依存がある**（【お客様名】は見出しより先に名前へ置換する）ので1関数にまとめてある。分けない。
⚠ 号室の**先頭ゼロが落ちる**（0103→103）のは**仕様**（`finalizeResponse`・「日本の号室は0から始まらない」）。バグではない。

**⚠「○○さん」をそのまま送らない**（`fixNamePlaceholder`）
本番検証で「**○○さん**お世話になっております」が出た。出所は `ai_reply_knowledge` の principle 10件で、
「○○さんお気に召されましたら…」がプレースホルダのまま入っている（ナレッジ自身が「○○を残すな」と書いているのに写す）。
実送信365日で「○○さん」は**0件**＝残っていたら必ず誤り。落とさず**名前に置き換える**（落とすと文が壊れる）。
「○月○日（曜日）○○:○○」のような時刻のプレースホルダには当てない（さん・様が続く時だけ）。
🔜 **次にやる**: この置き換えは今カバーレターにしか通していない。ナレッジの「○○さん」は
`viewing_invite` / `property_recommendation` の principle に多いので、内覧・物件オススメの AIX にも配る。

## 過去バグ記録（#42-LN 蓄積）

### バグ1: 仲介手数料を0にしても消費税が残る
- **日付**: 2026-05-31 修正済み ✅
- **原因**: `updateItem("commission", 0)` が `commissionTax` を連動更新していなかった
- **修正**: `updateItem()` 内で `commission` 変更時に `commissionTax = Math.round(value × 0.1)` を自動設定
- **教訓**: 税抜・消費税の2フィールドは常にセットで更新する。片方だけ変えると乖離が生まれる
- **次回の予防**: 金額×税率のフィールドペアを新設する場合は必ず `updateItem()` の連動処理を追加する

### バグ3: Excel黒画面・画像消える・書式崩れ（2026-06-03 修正済み）
- **原因**: xlsx ライブラリが数式削除時にスタイルを破壊・drawing XML を正しく扱えない
- **修正**: exceljs に完全移行。xlsx→xlsx 変換パイプラインで書式・画像・drawing を保持
- **教訓**: xlsx ライブラリはスタイル保持が不安定。テンプレート操作は exceljs が安全
- **次回の予防**: テンプレートに画像・図形が含まれる場合は必ず exceljs を使う

### バグ4: Excel節約金額・キャラ画像が drawing 競合で消える（2026-06-03 修正済み）
- **原因**: drawing ファイルを新規作成すると既存の drawing XML と rId が競合
- **修正**: 既存 drawing XML の rId を保持し Target のみ書き換える方式に変更（JSZip で直接操作）
- **教訓**: Excel の drawing 操作は既存 rId を必ず保持する。新規作成禁止
- **次回の予防**: 節約金額を書き換える場合は drawing2.xml の `r:id` を読んでから Target だけ変える

### バグ5: その他費用を÷1.1して税抜計算していた（2026-06-03 修正済み）
- **原因**: fill-estimate で otherItems の金額を税抜扱いで ÷1.1 していた
- **修正**: その他費用は税込金額をそのまま Excel に書き込む（÷1.1しない）
- **教訓**: otherItems はユーザーが入力した税込金額。commission 系とは別扱い

### バグ6: 月初（1日）入居なのに日割りが発生する（2026-06-03 修正済み）
- **原因**: moveInDay=1 でも proratedDays の計算が走っていた
- **修正**: moveInDay <= 1 のとき proratedDays=0 で確定（Excel と同じ挙動）
- **教訓**: 1日入居 = 日割りなし がルール。calcProratedDays() の先頭で必ずチェック

### バグ2: Vercel本番でExcelテンプレートが見つからない
- **日付**: 2026-05-XX 修正済み ✅
- **原因**: Vercel Serverless では `process.cwd()` が `/var/task` になりパスが変わる
- **修正**: `findTemplatePath()` で複数候補パスを試す + `outputFileTracingIncludes` でバンドル指定
- **教訓**: Next.js API Routes でのファイル読み込みは複数パス候補を持つこと
- **次回の予防**: テンプレート追加時は `findTemplatePath()` の候補パスを確認してから追加する

## 設計上の重要な仕様（罠に注意）

### toEditable() は初期化専用
`toEditable(extractedData, account)` は AI抽出後の初期化にのみ使用する。
ユーザーが編集した後に再呼び出し **禁止**。ユーザー編集は `updateItem()` が正とする。

```
AI抽出 → toEditable() で初期化（commission=0→デフォルト適用）
         ↓
         ユーザーが commission を手動変更 → updateItem() で state 更新
         ↓ ← ここで toEditable() を再度呼ぶとユーザー編集が消える（禁止）
```

### 2つのAPIの使い分け

| API | 用途 | 入力形式 |
|-----|------|---------|
| `fill-estimate` | Excelテンプレート埋め込み | 全項目（金額絶対値） |
| `generate-estimate` | 計算＋LINE文＋DB保存 | 家賃×ヶ月数方式 |
| `extract-estimate-info` | 画像OCR抽出 | 画像/PDF base64 |

現在のUIは **fill-estimate** を使用。generate-estimate の LINE文章生成はUIに未接続（代わりにclient-side generateLineText()を使用）。

### generateLineText() の節約額計算
```typescript
standardCommission = rent × 1.1  // 業界標準1ヶ月+税
actualCommission = commission + commissionTax
savings = Math.max(0, standardCommission - actualCommission) + discountAmount
```
節約額がマイナスにならないよう `Math.max(0, ...)` を使用。
